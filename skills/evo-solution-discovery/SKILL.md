# EVO Solution Discovery

## Objective

Give the human a current, evidence-backed choice of foundations that preserve effort for the product's differentiating domain work.

## Inputs and authorities

Read approved requirements, domain constraints, team/runtime constraints, deployment needs, licensing constraints, and the Greenfield reuse ladder. Research current primary sources because project maturity, versions, and licenses change.

## Required outcomes

Separate commodity capabilities from differentiators. Compare viable options on fit, existing features, extension model, maintenance, compatibility, license, operational cost, migration risk, and evidence quality. Recommend a smallest validation experiment.

## Constraints and decision rules

- Search in order: existing capability, framework capability, maintained library, mature open source, extension, then new implementation.
- Popularity metrics alone do not prove production suitability.
- Do not call one option selected until the human decides.
- After bootstrap, re-run Brownfield initialization against the actual fork; generic framework memory is no longer authority.

## Stop conditions

Stop for a human foundation, language, licensing, hosting, or cost Decision. Do not clone, scaffold, install, or modify a repository during discovery.

## Repository writes

Only an explicitly requested comparison artifact. Do not create project code.
